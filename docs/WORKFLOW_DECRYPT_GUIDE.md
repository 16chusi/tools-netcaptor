# 工作流解密功能使用指南

## 功能概述

工作流现在支持拦截请求数据并进行解密的完整流程：

1. **拦截请求** - 捕获网络请求的响应数据
2. **格式转换** - 将数据转换为 Text/JSON/Hex 格式
3. **解密组件** - 使用 SM4 算法解密数据

## 使用场景

适用于需要拦截加密响应并解密的场景，例如：
- 拦截 API 返回的加密数据
- 解密后进行数据提取
- 批量处理加密数据

## 工作流配置示例

### 1. 拦截请求组件

**配置项：**
- **URL匹配**: `*/api/data*` (支持通配符)
- **拦截动作**: 选择 `捕获数据`
- **数据格式**: 
  - `文本 (Text)` - 原始文本
  - `JSON` - 格式化的 JSON
  - `十六进制 (Hex)` - 转换为 Hex 字符串（用于解密）
- **保存到变量**: `encryptedData`

### 2. 解密组件

**配置项：**
- **数据来源**: `encryptedData` (输入变量名，不需要 `{}`)
- **解密算法**: 
  - `SM4-ECB` - ECB 模式
  - `SM4-CBC` - CBC 模式
- **密钥 (Hex)**: `46696e32416e63304571753245727934`
- **IV向量 (Hex)**: CBC 模式下可选，留空使用零向量
- **保存到变量**: `decryptedData`

### 3. 后续处理

解密后的数据可以：
- 使用"提取数据"组件提取特定字段
- 使用"条件判断"组件进行逻辑判断
- 使用"下载保存"组件保存到文件

## 完整示例流程

```
开始 → 导航(打开页面) → 拦截请求(捕获数据,Hex格式) → 解密(SM4-ECB) → 提取数据 → 结束
```

**详细配置：**

1. **导航节点**
   - URL: `https://example.com/data`

2. **拦截请求节点**
   - URL匹配: `*/api/encrypted*`
   - 拦截动作: `捕获数据`
   - 数据格式: `十六进制 (Hex)`
   - 保存到变量: `encryptedData`

3. **解密节点**
   - 数据来源: `encryptedData`
   - 解密算法: `SM4-ECB`
   - 密钥: `46696e32416e63304571753245727934`
   - 保存到变量: `decryptedData`

4. **提取数据节点**
   - 从 `{decryptedData}` 中提取需要的字段

## 数据格式说明

### Text 格式
- 原始文本数据
- 适用于纯文本响应

### JSON 格式
- 自动格式化 JSON
- 适用于 JSON 响应
- 会验证 JSON 有效性

### Hex 格式
- 转换为十六进制字符串
- **适用于加密数据解密**
- 解密组件需要 Hex 格式的输入

## 注意事项

1. **数据格式匹配**: 解密组件需要 Hex 格式的数据，拦截时选择 `十六进制 (Hex)`
2. **密钥格式**: 密钥必须是 Hex 格式的字符串
3. **变量引用**: 在解密组件中输入变量名时，不需要加 `{}`
4. **WebSocket 连接**: 确保浏览器扩展已连接

## 支持的加密算法

- **SM4-ECB**: 国密 SM4 算法，ECB 模式
- **SM4-CBC**: 国密 SM4 算法，CBC 模式（需要 IV）

## 故障排查

1. **拦截失败**: 检查 URL 匹配模式是否正确
2. **解密失败**: 
   - 确认数据格式为 Hex
   - 检查密钥是否正确
   - 验证加密算法是否匹配
3. **变量未找到**: 确认前置节点已成功执行并保存变量
