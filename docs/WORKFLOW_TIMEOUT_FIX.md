# 工作流执行超时问题解决方案

## 问题描述
执行工作流时出现"执行超时"错误，表示浏览器扩展未在规定时间内响应。

## 根本原因
工作流执行器通过 WebSocket 向浏览器扩展发送指令（如导航、点击等），并等待扩展返回 `action_result` 消息。如果扩展未响应，则会超时。

## 可能的原因

### 1. 浏览器扩展未安装或未启用
**解决方案**: 安装并启用 NetCaptor 浏览器扩展

### 2. 浏览器扩展未连接到 WebSocket
**解决方案**: 
- 检查扩展是否正常运行
- 刷新浏览器页面
- 重启扩展

### 3. 浏览器扩展未实现 action_result 响应
**解决方案**: 确保扩展的 content script 正确处理消息并返回结果

## 改进内容

### 后端改进
1. **连接检查**: 在发送消息前检查 WebSocket 是否有客户端连接
2. **详细日志**: 添加消息发送和接收的详细日志
3. **友好错误**: 提供更具体的错误信息，指导用户排查问题

### 前端改进
1. **智能错误提示**: 根据错误类型显示不同的提示信息
2. **连接状态显示**: 可考虑添加 WebSocket 连接状态指示器

## 调试步骤

1. **检查 WebSocket 连接**
   ```
   查看后端日志: [WebSocket] 客户端已连接
   ```

2. **检查消息发送**
   ```
   查看后端日志: [Workflow] 发送消息: navigate, 数据: map[url:...]
   ```

3. **检查消息接收**
   ```
   查看后端日志: [Workflow] 收到响应: action_result
   ```

4. **如果超时**
   - 确认扩展已安装并启用
   - 确认扩展已连接到 WebSocket
   - 检查扩展控制台是否有错误
   - 确认扩展正确实现了消息处理逻辑

## 浏览器扩展要求

扩展必须：
1. 连接到 WebSocket 服务器
2. 监听来自服务器的消息
3. 执行相应操作（navigate, click, input 等）
4. 返回 `action_result` 消息，格式：
   ```json
   {
     "type": "action_result",
     "data": {
       "success": true,
       "error": "错误信息（如果失败）"
     }
   }
   ```

## 超时时间
- navigate: 15 秒
- click: 10 秒
- input: 10 秒
- wait: 无超时（本地执行）
